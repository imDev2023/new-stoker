# new-stoker

The rebuild of Stoker (ticker STOKER, domain `stoker.markets`), the open, asset-paired Solana launchpad on Raydium LaunchLab, in a repository of its own (owner, 2026-11-04); the packages keep their `@launchpad/` scope.
This repository began as a copy of `imDev2023/Stoker-Markets` at `12dbc10`, history included, so a fix can be cherry-picked either way (that repository is the remote `upstream`).
The original checkout, `/Volumes/Farhan/Work Folder/Dev/AI/stonk-fun-solana`, stays as it was: it deploys the live mainnet API and the devnet rehearsal, and it is the fallback if this rebuild goes wrong.
Here the website is rebuilt from scratch in the Playground's design ([ADR 0017](docs/adr/0017-the-site-rebuilt-in-the-playground-design.md); the spec is vendored in `docs/design/playground/`), the backend is carried and improved, and programs of our own are allowed wherever they make the launchpad better ([ADR 0018](docs/adr/0018-custom-on-chain-programs.md)).
The original had none: its own LaunchLab `PlatformConfig`, a Cloudflare backend and a Next.js app.

## How the work runs

The owner's model is Top-pad's (2026-11-04: "like we have worked in top pad folder", `/Volumes/Farhan/Work Folder/Dev/AI/Top-pad`), with several sessions in parallel.

- The map is GitHub issue #1 (label `wayfinder:map`): the destination, every decision, the open questions, the lanes, and in `## Next` the order of the work.
  Start any session with `gh issue view 1 --repo imDev2023/new-stoker`.
- The work is build tickets (label `build`), sub-issues of the map wired with native blocking edges (`docs/agents/issue-tracker.md`).
  The open ones with no open blocker are the frontier, and the map's lanes say which can run side by side.
- One ticket per session, in a worktree of its own: the relay's Orca worktree (relay project `new-stoker`), or `.claude/worktrees/<branch>` for a session the owner starts.
  Never work in the main checkout, `/Volumes/Farhan/Work Folder/Dev/AI/new-stoker`, which belongs to the owner's own sessions.
  A session that lands a ticket whose relay worktree still holds the branch (one that ended in review) leaves that worktree as it is and checks the branch out under another name: `git worktree add -b land-<n> .claude/worktrees/land-<n> origin/<branch>`, then `git config push.default upstream` in it, so a plain `git push` updates the PR's branch (#13, 2026-11-07).
  The session's first write claims the ticket (`gh issue edit <n> --add-assignee @me`); push the branch early and open the PR as a draft, so a parallel session sees it.
  Push every working branch: a cloud session can't see a local-only branch (Stoker-Markets#11 was rebuilt from scratch because of one).
- A ticket lands as its own PR whose body says `Closes #<ticket>`, and the session squash-merges it itself (`gh pr merge <n> --squash`) once the ticket's demo works end to end and CI is green.
  A web ticket's demo is its pages on a seeded local stack at 1440 and 390, light and dark, with its UI specs passing locally (CI never runs the UI suite, whose baselines are darwin's), and the PR shows the screenshots.
  If `main` has moved, merge `main` into the branch (never force-push), verify again, and wait for CI on the new head.
- The Playground is the owner's approved design, so a page that follows it merges.
  Where a ticket must depart from it, or the spec leaves a choice open, build the most conservative reading and list the alternatives in the PR and on the ticket for the owner.
- Finishing a ticket: put what it made surprising into this file in the PR before merging (traps, measurements that contradicted an assumption); post the closing record with `gh issue comment` (a closed ticket drops the comment of `gh issue close --comment`); update the map (the ticket in the done lines with its outcome, `## Next` naming what follows, the body refetched just before writing it, since parallel sessions edit it too); run `multica-sync`; then hand off with the `next-session-prompt` skill, or end with `relay.py finish` when the relay started the session.
- Never touch the original from here: its folder, worktrees, branches and issues, its Workers (`stoker-api`, `stoker-api-devnet`, `stoker-web`, `stoker-web-devnet`), its databases (Supabase `stoker-devnet` and `stoker-mainnet`), its Helius webhooks, and everything under `~/.config/stoker/`.
  This repository's Workers are `new-stoker-*`, neither `wrangler.jsonc` has a production environment until the owner's cutover, and the local stack has ports of its own (Run and test), so both projects run side by side.
- Issue and PR numbers in everything inherited (the docs, ADRs 0001 to 0015, code comments, the history before the fork) are `imDev2023/Stoker-Markets`'s.
  In issues and PRs write them as `imDev2023/Stoker-Markets#N`, the form GitHub links (the relay's map parser skips it, so the map's `## Next` must name only this repository's tickets, as plain `#N`); in files `Stoker-Markets#N` will do.

## Run and test

- Dev: `docker compose up -d` (Postgres on 5462), `pnpm localnet` (chain on 8699, writes `tools/localnet/.ledger/state.json`; quotes mainnet's whole set of Quote Assets from the snapshot in `tools/localnet/fixtures/mainnet` (605 on 2026-10-10; `pnpm --filter @launchpad/localnet snapshot` with a mainnet `RPC_URL` and `JUPITER_API_KEY` retakes it, `LOCALNET_QUOTES=cases` gives the tests' six instead), and migrates sold-out curves within seconds like Raydium's crank, `CRANK=off` to leave them graduating), `pnpm stand-ins` (the Turbo and gateway stand-in on 8697, where the dev API's `TURBO_*_URL` and `ARWEAVE_GATEWAY_URL` point, without which every prepare still works but no upload lands; and the Jupiter stand-in on 8698, `JUPITER_API_URL`, which prices, tags and gives logos to the snapshot's assets as Jupiter did on the day, without which nothing is launchable), `apps/api`: `pnpm exec wrangler dev --port 8691 --inspector-port 9329 --test-scheduled --var PLATFORM_CONFIG:<from state.json> --var PLATFORM_LOOKUP_TABLE:<lookupTable from state.json>` with `MINT_KEY_SECRET` (32+ random characters) in `apps/api/.dev.vars`, `apps/web`: `pnpm dev` (3200). Migrate the dev DB with `runMigrations` from `@launchpad/db/migrate`.
- Scheduled jobs: `wrangler dev --test-scheduled` runs them on `GET /__scheduled?cron=<cron>`: `*+*+*+*+*` is the graduation watch, `*/5+*+*+*+*` the Quote Registry refresh, `15+*+*+*+*` the Fee Collector and then the Creator Forward, `*/10+*+*+*+*` the Reward Engine, `45+*+*+*+*` the Burn, and a bare `GET /__scheduled` runs all five. The Fee Collector sweeps only with `TREASURY_WALLET` set (required on mainnet). The dev API also needs `PLATFORM_ADMIN` (the admin from `state.json`; `PLATFORM_CONFIG` must be its PDA).
- Tests: `pnpm test:backend` and `pnpm test:ui`, each on its own throwaway stack; the chain takes a free block of ports, so checkouts and agents can run suites side by side (`TEST_RPC_PORT` pins it). `pnpm lint`, `pnpm typecheck`; CI runs both plus the backend suite. Without docker (or with Docker Desktop hung, its ports listening and never answering, 2026-11-06), `STACK_DATABASE_URL=postgres://user:pass@host:port/postgres` makes the stack create a throwaway database on that server instead (the Hyperdrive binding refuses a URL without a password); the Mac's own PostgreSQL 18 serves (`/Library/PostgreSQL/18/bin`: `initdb -U launchpad --pwfile` into the scratchpad, then `postgres -p 5472 -c unix_socket_directories=` in the background, since a socket in the scratchpad passes the 103-byte limit), and a UI run took 10 minutes on it; `STACK_LOG_DIR` keeps each process's log. The backend suite takes about eight minutes on Surfpool.
- To see a page with data on a running dev or worktree stack (the owner's database is empty), a short `.mts` script inside `tests/ui` that copies the fixtures' thin helpers (airdrop, `POST /v1/launches/prepare` with `tests/ui/fixtures/coin.png`, `POST /v1/trades/prepare`, sign, send, `POST /v1/transactions/:signature`) against that stack's URLs, run with `pnpm exec tsx` from `tests/ui` and deleted after: a file in the scratchpad cannot resolve the packages, `.ts` is transformed as CJS and refuses top-level await, and a sell must stay under what the trader holds (2026-10-10).
- Never edit `apps/api`, `packages/*` or `tools/*` sources while a backend run is in progress: `wrangler dev` hot-reloads the API mid-run and the results are meaningless. Tests, web and docs are safe to edit meanwhile. During a UI run `apps/web` is not safe either: `next dev` hot-reloads it, and one web edit that named a contract field not yet in `packages/contract` broke every page for the rest of the run (2026-10-07). Finish the whole change, typecheck, then run.
